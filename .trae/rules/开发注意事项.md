## 0. ★ 函数注释规范（置顶，新写/修改函数必看）★

所有 **用户函数**（项目自写函数）的注释统一下列 **Doxygen 格式**；**新增函数必须用此格式**，**已有函数注释逐步改成此格式**（模板参考下面、及第 10 节）。

模板（`@brief` 一句话概括，换行对齐续写补充；`@param 名称 说明` 每个参数一行且名称对齐；有返回值才写 `@return`；踩过的坑才写 `@note`）：

```c
/**
* @brief  只重绘单个数字格（选中格=高亮底+数字，未选中格=框底色+数字）。
*         用于 增加/下一位 局部刷新：不动边框/文字/整框，避免整框重画闪烁。
* @param  it       含数字拼接片段项（如 page4_texts[0]）
* @param  cursor   当前选中位（1~digit_count）
* @param  cell_idx 要重绘的数字格下标（0=第1位, 1=第2位, 2=第3位…）
*/
```

注意：注释为中文，`@brief/@param/@return/@note` 行对齐；参数名称对齐。

> **编码坑**：源文件为 GBK，加/改中文注释必须用 GBK 脚本（`io.open(..., encoding='gbk')`），禁用 SearchReplace/Edit 直接写中文（会写坏成 `?`，见第 14 节）。

## 2. 模式切换（config.h）

三模式宏，**同一时间只能开一个**：
- `FLASH_DATA_STORE_MODE` — 字库/图片烧录到外部 Flash
- `VIDEO_CHUNK_STORE_MODE` — 视频块烧录
- 都不定义 — 正常游戏/视频播放

切换用脚本，会同步改 config.h 和 makefile：
```
powershell -File "数据\娜娜莉\switch_mode.ps1" burn   # 烧录模式
powershell -File "数据\娜娜莉\switch_mode.ps1" game   # 游戏模式
powershell -File "数据\娜娜莉\switch_mode.ps1"        # 查看当前
```

## 3. 编译下载

- **两模式都不加 `-flto`**（flto 在游戏模式致 sokoban.c 链接失败 `R_RISCV_RVC_BRANCH`，超大函数分支超范围）
- MRS 每次编译会重新生成 makefile 恢复 flto，**烧录用命令行不用 MRS**
- 一键编译下载（工程根目录）：
  ```
  powershell -File 编译与下载.ps1          # 编译+下载
  powershell -File 编译与下载.ps1 build     # 仅编译
  powershell -File 编译与下载.ps1 flash     # 仅下载（elf 已编好）
  powershell -File 编译与下载.ps1 clean     # 清理重编+下载
  ```
- SWD 连不上 `WCH-Link failed to connect with riscvchip` 多半是设备休眠/没电，充电唤醒后 `flash` 重下

**关于 `-flto` 与 obj/*.mk（重要踩坑）**：
- **`-flto` 不只出现在主 makefile，还出现在各 `obj/**/subdir.mk` 的编译命令里**：编译出的 `.o` 是 LTO 目标，链接器会自动做 LTO 优化，照样触发 `R_RISCV_BRANCH` 超大函数分支超范围。因此要删就**所有 obj/**.mk 一起删**（`-flto` 字符串逐一确认，别漏）。
- **这些 `obj/**/*.mk` 是 GBK 无 BOM 编码**（注释为中文）。删 flto/改路径时**严禁**用 `PowerShell [IO.File]::ReadAllText(.., UTC8)` 全文本读改写，否则中文目录名（彩屏/源代码/大屏幕 - 触摸屏）会变 `锟斤拷` 乱码，导致 include 路径错误、`fatal error: xxx.h: No such file or directory`。要用 `[Text.Encoding]::GetEncoding(936)` 读、写回 GBK，或用字节级/`SearchReplace` 操作。
- **工程根目录名含空格**（`0.SOLO-AI eyes-源代码`、`大屏幕 - 触摸屏`）：make 的**规则依赖中的无引号绝对路径**会被空格截断，报 `No rule to make target '.../0.SOLO-AI'`。位于工程根 `SRC/` 的子目录（Core/Debug/Peripheral/Startup）源在 `.mk` 里用的是无引号绝对路径，需改成相对路径 `../../../SRC/...`（make 在 obj 目录运行，obj→SPI_LCD→SPI→工程根）。而 `-I".../SRC/Debug"` 这类**带引号**路径 make 会经 shell 处理、能容忍空格，可保留。

## 4. 字库/图片资源（外部 Flash）

- 资源通过 flash_store.c 的 `s_resources[]` 表烧录到外部 W25Q64（8MB）
- **改字库/图片大小，必须同步 `s_resources` 对应项的 size**，否则后续所有资源偏移错位
- 资源读取用 DMA（`flash_store_read` → `SPI1_Read_DMA`），不要改成阻塞读
- **关卡地图在内部 Flash**（sokoban_maps.c `static const`，50关约2.6KB），**不在外部 Flash**
- 字体位序统一 **MSB-first**（字节高位 = 最左像素）
- 关卡数字字体 16×32 红色

**RGB565 图片资源约定（大鱼吃小鱼即此）**：
- **字节序必须小端序**（`uint16_t` 按低字节在前存），否则 LCD 上 RGB565 红蓝颠倒。现有 `sok_img_next.h` 等图标均标注"小端序"
- **透明色用 `0xFFFF` 白色**（不是黑色 0x0000！），绘制函数跳过白色像素。参考 `sok_nav_draw_rgb565` 但透明判断是 `==0xFFFF`
- **共用绘制函数按 level 参数化**：`draw_image_sprite(id_base, dims, count, level, x, y)`，用 `FlashStore_ResLoad(id_base+level, 0, w*h*2)` 流式读入 scratch 后强转 `(uint16_t*)` 绘制。玩家和小鱼分两套图：
  - 玩家：`FLASH_STORE_ID_PLAYER_0` + `player_imgs_dim`（`玩家.txt`，9张 20×16→52×41，成长等级 0-8，吃小鱼逐级长大）
  - 场上小鱼：`FLASH_STORE_ID_FISH_0` + `fish_imgs_dim`（`鱼图片.txt`，10张 16×12→52×31，等级 0-9）
- **scratch 缓冲区必须 ≥ 最大资源字节**：最大为玩家 52×41×2=4264，`FLASH_STORE_SCRATCH_SIZE` 已扩到 **4352**（当前 RAM 约 78%）。改资源后记得核对
- **生成脚本**：`gen_fish_imgs.py`（鱼图片.txt）与 `gen_player_imgs.py`（玩家.txt），输出 `.c` 到 font_library、`.h` 到 Game/inc（头文件必须在 include 路径 Game/inc）
- 只改字库/图片资源后，需用烧录模式（FLASH_DATA_STORE_MODE）重新烧写外部 Flash，游戏模式才能读到新资源

## 5. 内部 Flash 存档

- 存档区 `0x0800FF00~0x0800FFFF`（单页轮换，防写入中断损坏）
- **链接脚本 Flash 长度必须 `0xFE00`**（不能 0x10000，会覆盖存档区）
- 仅 CRC 变化时才擦写（减寿命损耗，相同内容跳过）
- 存档含：魔数/版本/序号/长度/CRC16，**最大 256 字节**
- 俄罗斯方块棋盘按每格 3bit 压缩；推箱子只存关卡+人物+箱子位置
- 存档加载后需完整重绘游戏画面

## 6. 休眠唤醒

- 无触摸 10 秒 → 关背光 → LCD/触摸/Flash 休眠（RAM 与画面保留）
- `KEEP_LCD_POWER_IN_STANDBY` 必须开（触摸唤醒的前提）
- PA8 EXTI Event 唤醒后做**软件复位**（完整重初始化 LCD，避免状态残留）
- 用 `PWR_EnterSTANDBYMode_RAM()` 不是 `PWR_EnterSTANDBYMode()`（保栈有效）
- CST816S 进休眠前写 `0xF5=32` 调灵敏度，唤醒后 `Touch_Init()` 重置 + `0xFE=1` 禁自动休眠
- 唤醒后第一帧触摸隔离，连续两帧确认松开才允许游戏操作
- 休眠前 `IWDG_Disable()`，唤醒后 `IWDG_Init()` 恢复 ~1 秒看门狗
- 休眠期间 TIM1 运行用于低电检测，不再用于喂狗
- 华容道计时扣除休眠时间；俄罗斯方块逻辑休眠期间停止

## 7. 电池

- 4 格红/黄/绿显示，60 秒采样电压，每秒补绘，菜单显示期间暂停
- 充电与游戏用**独立电压阈值**（各自保存在 BKP_DR3/DR4，30mV 滞回）：
  - 充电：3.50/3.70/3.85/4.00V
  - 游戏：3.45/3.65/3.80/3.95V

- 充电期间：不休眠、完全禁用触摸、禁用 PA8 中断 500ms
- 推箱子电池图标固定顶部中央 X=108，地图从 Y=20 开始（避免覆盖）

## 8. LCD 绘制

- `LCD_Fill` 填到 Y=239 需传 `(x, y, 240, 240)`（内部 xend/yend 减 1）
- **菜单条带渲染已改为乒乓双缓冲**（`menu_draw_nrow_frame_only()` 内）：复用 `shared_buffer` 前后两半（`STRIP_H=8` × `ROW_BYTES≤300` = 2400B/块，两块共 4800B ≤ FILL_BUFFER_SIZE），**0 额外 RAM** 恢复"画/发流水线并行"。**别再加独立的 `s_menu_strip_buf1`**（会白耗 5120B RAM，且已删除）
- 方案对比：菜单条带**单缓冲**（每条带串行等 DMA）会导致下滑菜单变卡；**双缓冲**（画下一块时上一块在 DMA 发）才流畅。RGB 播放/游戏共用 `shared_buffer`，菜单与它们串行调用不会冲突
- 全屏清黑用**同步** `LCD_Fill(0,0,LCD_W,LCD_H,LCD_BLACK)`，不要用异步 `LCD_Clear()`（会与后续绘制竞争导致残留）
- 菜单背景用 `MENU_BG_COLOR`（LCD_CYAN）避免黑闪
- 菜单坐标钳位到 `[0, 239]` 防 `uint16_t` 溢出
- **RAM 警戒线**：工程 RAM 只有 20KB，`bss`+`data` 一度到 90.9%；当前约 79%。新增常驻大数组/缓冲前先权衡，能走外部 Flash 流式就不要常驻 RAM
- **增量绘制防重叠残留**：透明图增量擦除某实体旧矩形（`clear_entity_rect` 背景填充它的包围盒）会误伤与其重叠的其他实体像素，留下"被啃一块"的缺口。可靠做法：填背景后**立即按固定顺序重绘该矩形内所有相交实体**（用当前坐标），一次性正确恢复，避免跨帧标记/连锁残留。参考 fish.c
- **主循环无帧率控制**：`while(1)` 全速空转，未按下（无触摸 I2C 负载）时帧率远高于按下时。凡是"每 N 帧移动一次"的动画在未按下时会疯狂加速。**改用真实时间节拍**（`GetTimerCount()` 返回微秒；如鱼每 40ms 移动一次），与帧率无关；随机速度要保证不全为 0，避免鱼停死
- **游戏结束画面**：屏幕中央"游戏结束"（32×32 红字，`FLASH_STORE_ID_32_YOU/XI3/JIE/SHU`）+ 下方"重新开始"提示（24×24 白字，`FLASH_STORE_ID_24_CHONG/XIN/KAI/SHI3`）；点击任意位置重开
- **LCD 片选(CS)陷阱**：`LCD_Fill`/`LCD_Clear` 内部会自己 `LCD_CS_CLR/SET`。凡是**不带 CS 控制的绘制函数**（如 `sok_draw_digit_scaled`/`sok_draw_char_32`）若紧跟一次 `LCD_Fill` 之后调用，此刻 CS 已被置为无效，数据写不进显存 → 该内容"消失不见"。**在 `LCD_Fill` 之后、用这类函数绘制前务必先 `LCD_CS_CLR`**。反之 `LCD_Fill` 自己会重设 CS，接在后面无碍。
- **菜单清除已改 DMA**：`LCD_CLEAR_MENU_AREA()`/`LCD_CLEAR_RESTART_AREA()` 用 `LCD_Fill_DMA`（同步，函数内 `while(BSY)` 等发送完，**非 `LCD_Clear` 那种异步**，不会与后续绘制残留；用共享 `shared_buffer`，`FastFill_16bit_Repeat` 会把长度钳到 `FILL_BUFFER_SIZE` 防溢出）。`menu_clear_exit_area_to` 仍用同步 `LCD_Fill`。全屏清黑仍用同步 `LCD_Fill`。注意：引用 `LCD_Fill_DMA` 会使 Flash 增大（约 +0.8%，当前 94.23%，余量约 3.7KB）。
- **菜单清除色可配置（避免切菜单黑闪）**：`LCD_CLEAR_MENU_AREA()`/`LCD_CLEAR_RESTART_AREA()`/`menu_clear_exit_area_to` 现在用全局 `g_menu_clear_color`（默认 `LCD_BLACK`）。游戏可设为自己背景色（如 fish.c `fish_init` 里 `g_menu_clear_color = COLOR_BG`），清菜单位置直接填背景色，比"清黑+重绘"更快、无黑闪；其它游戏保持黑色。`game_handle_ret` 在**模式切换（换游戏/视频）时重置为黑色**，避免泄漏到其它游戏；进设置（EXIT_RET_SETTINGS）不重置（回同一游戏）。
- **设置页/二级设置菜单返回防黑闪**：从游戏进设置（`menu_enter_game_settings` 打开 `g_video_menu_row_types` 的二级设置选项菜单）点“返回”回游戏，走 `GameSettings_Update` 的 else 分支。原来先 `LCD_Fill(0,0,LCD_W,LCD_H,LCD_BLACK)` 整屏刷黑、再 `*_full_redraw()` 延迟到下一帧才重绘 → 黑闪。**应只清二级菜单条带**（`LCD_Fill_DMA(VIDEO_MENU_X, VIDEO_MENU_Y, VIDEO_MENU_X+VIDEO_MENU_W, 240, g_menu_clear_color)`，用 `g_menu_clear_color` 背景色），再**同帧** `*_full_redraw()`+`*_update()` 恢复场景。二级菜单是底部覆盖条、场景始终在它后面，无需整屏刷黑。返回键在触摸释放帧触发（`ts.pressed==0`），此时直接调 `*_update()` 只重绘、不误触手势，是安全的。此段代码所有游戏共用（下划设置菜单、三级设置页返回都是同一分支）。
- **菜单背景重绘要尊重进菜单前的状态**：俄罗斯方块游戏结束后上滑/下滑菜单，背景应显示“游戏结束”画面而非棋盘。菜单状态里的背景重绘用 `g_state_before_menu == TETRIS_STATE_OVER` 分流——是结束就画“游戏结束”，否则画棋盘。**切莫把触发条件写成恒真**（如 `g_board_dirty >= 2 || g_state_before_menu == TETRIS_STATE_OVER`），因为进菜单前是结束时该条件恒为真，会在菜单状态下每帧重画背景（含外部 Flash 读“游戏结束”字库），与菜单渲染反复互相覆盖 → 闪屏。应沿用 `if (g_board_dirty >= 2)` 只触发一次，内部再分流。
- **圆形屏 240×240**：顶部圆弧窄，顶部信息/文字须**水平居中**放进圆弧可见带（y 越往下越宽），切勿贴左右角；四角默认在圆外不可见，实体可游动区用**8角形**（矩形四角倒角 `PLAY_CORNER`），且角落要加**角落反弹**（`fish_bounce_corners`）反转速度，否则鱼会卡角很久不动。

## 12. 大鱼吃小鱼（fish.c）

- **玩法**：触摸**增量拖动**控制玩家大鱼（按住滑动时按手指位移增量平移，刚按下记录起点不动，松开停，不吸附到手指）；碰同级/更小 吃掉成长，碰更大 失败；结束后点击任意处重开。玩家物理初始等级 0（第1条沙丁鱼形象）。玩家/小鱼**按游动方向左右翻转**（`facing`：0=右、1=左）。
- **左右转向**：`draw_image_sprite` 新增 `flip` 参数做**水平镜像**绘制（flip=1 时非透明段起点左移、像素倒序）；`FishEntity.facing` 存朝向（0=右、1=左）。玩家按拖动 `dx` 定朝向（`dx<0` 向左），小鱼按 `vx` 定朝向（`vx<0` 向左）。**所有实体绘制（含 `clear_entity_rect`/`fish_move_redraw` 内部重绘相切实体）都要传 `facing`**，否则转向后残影/方向错乱。
- **得分/升级（分数制）**：吃 `N` 级鱼得分 = `5^N`（`fish_thresh`：0级=1分、1级=5、2级=25…）；累计分 ≥ `5^(level+1)` 就升一级（`g_score` 为 `uint32_t`）。HUD 显示等级 = **物理等级 + 1**（方便判断升级了几次）。
- **通关（1,953,125 分）**：达到 `FISH_WIN_SCORE=1953125`（显示10级）即**通关**，设 `g_won=1`＋`g_state=FISH_STATE_OVER`，画面中央画绿色"通关"两字（`FLASH_STORE_ID_32_TONG/GUAN`）；玩家最大等级封顶**物理9级=显示10级**（`FISH_PLAYER_LEVEL_MAX=9`）。玩家等级 ≥ `FISH_PLAYER_LEVEL_MAX-1` 时**可吃到大白鲨（等级+1 的鱼）**，从而能累计到通关分。
- **玩家形象/尺寸封顶**：`PLAYER_IMG_LVL` 把玩家等级封顶到最大图片（`PLAYER_COUNT-1`），避免物理 `level=9` 超出图片范围导致"玩家消失"；`draw_image_sprite` 里 `level>=count` 也钳位用最大一张。**所有用到玩家等级的地方**（碰撞半径、清矩形尺寸、绘制）都要用 `PLAYER_IMG_LVL`。
- **HUD（圆形屏）**：两行。行1=分数（居中，黄色），行2=升级进度条 + 当前等级（居中，等级紧贴进度条右侧，白色）；数字用 `sok_draw_digit_scaled`（7x11 或 8x14），用 `g_hud_dirty` 脏标记变化才重绘。进度条按"当前级分数占比"填 10 格。**等级 ≥ 10 须画两位数字**（先画"1"再画个位，布局宽度 `pl_total` 相应按 2 位加宽），否则 `sok_draw_digit_scaled(...,10,...)` 越界不显示。
- **可游动区 & 卡角**：`fish_clamp_pos`（矩形钳位 + 四角倒角成 8角形）用于玩家/生成点；小鱼移动后还要 `fish_bounce_corners`（角落斜边速度反弹）防卡角。`PLAY_TOP` 控制游戏区上界（信息栏底 + 1px），`PLAY_CORNER` 控制倒角大小。
- **透明判定**：`IS_TRANSPARENT(p)` 接近白色（R≥0x1C/G≥0x38/B≥0x1C）即透明，替代仅 `==0xFFFF`，避免边缘残留。
> [!WARNING]
> **注意坑（踩过，改代码前先看）**：
  - **食物等级分布必须"大部分吃到"**：曾用"玩家±3"分布，开局只有 0 级可吃 → 玩家吃不到鱼、无法成长。现改为 75% 等级 0..玩家级（可吃）、25% 玩家级+1..+2（挑战）。`FISH_FOOD_RANGE` 宏已废弃，勿再沿用。
  - **吃掉鱼"先更新新位置、再擦旧图"**：`food_respawn` 须先设好新的 `x/y/level`，再用**旧的** `prev_x/prev_y/prev_level` 调 `clear_entity_rect`（清旧矩形；其内部重绘相交实体用的是已更新的当前坐标）。顺序颠倒会把新位置画回旧矩形背景。
  - **HUD 等级显示 = 物理等级+1**：显示层特意 +1（0 级显示成 1，便于判断升级次数）；勿改回物理值，否则显示不符预期。
  - **玩家碰撞半径是近似值**：`pr = 8 + level*4`，不是用图片实际宽高做碰撞；等级越高越快，需与图片尺寸匹配，避免"看起来没碰到却吃了/败了"。
  - **进度条第一级基准 `lo=0`**：`level=0` 时进度取 `lo=0`（而非 `5^0=1`），因 `g_score` 从 0 起算，第一格按"0→5"填格。
  - **小鱼移动用真实时间节拍**：`GetTimerCount()`（40ms）与帧率无关，未按下主循环空转也不会狂飙（见第8节）；鱼移动重绘用行级 `fish_move_redraw` 减闪。**小鱼游动时也要按 `vx` 更新 `facing`**，否则左右游动方向不翻转。
  - **升级残影**：玩家升级变大时，仅清旧尺寸矩形不够（新尺寸区域残留旧图），须**等级变化时按新尺寸再 `clear_entity_rect` 一次**（用 `PLAYER_IMG_LVL`），否则到 9→10 级会残留。
  - **离场也要转向**：寿命到期朝最近边缘游出（以及普通游动）都要按 `vx` 同步 `facing`；漏改会"离场时头朝错误方向游出去"。
  - **无敌/通关是测试与功能参数**：`FISH_INVINCIBLE` 默认应为 **0**（正常玩法，碰大鱼即失败）；仅试玩才临时置 1（碰到更大鱼忽略，不撞死也不吃）。**提交前务必改回 0**。`FISH_WIN_SCORE` 是通关分数（1953125）。
- **菜单（已接入）**：与其它游戏一致的**上划重开菜单 / 下滑退出菜单**。上划（底部 y>220 区）弹出"重新开始/设置/返回"，点"重新开始"才重开一局；下滑（顶部 y<40 区）弹出"退出"可切换到其它游戏或返回。**游戏结束不再"点击任意处重开"**，改为上滑呼出菜单、点"重新开始"触发。
> [!WARNING]
> **注意坑（拖拽 vs 菜单不冲突）**：鱼的拖动是核心操作，菜单手势触发区必须放到**玩家到不了的极边**——上划只在底部 y>220（玩家最大 y 是 `PLAY_Y_MAX=LCD_H-21=219`），下滑只在顶部 y<40（玩家最小 y 是 `PLAY_Y_MIN=PLAY_TOP+20=52`）。这样拖鱼永远不会误触菜单；若把触发区设进可游动区（如 tetris 用的 210），拖鱼到边缘就会误弹菜单。
> [!WARNING]
> **注意坑（菜单切换清黑残留）**：退出菜单→上划切到重开菜单时 `menu_swipe_to_restart_handler` / `game_menu_restart_to_exit` 内部会 `LCD_CLEAR_MENU_AREA()`/`LCD_CLEAR_RESTART_AREA()` 把菜单区清黑，其它游戏靠重绘棋盘（`g_board_dirty=2`）恢复；鱼游戏须在退出/重开菜单 state 的 `g_full_redraw` 分支里，按 `g_state_before_menu` 调 `fish_draw_scene()`（进行中）或 `draw_game_over()`（结束），否则漏出黑色菜单背景。

## 14. 编码坑：SearchReplace 会写坏 GBK 中文（2026-09 新增）

- **坑**：用 `SearchReplace`/Edit 工具编辑 GBK 源文件的**中文注释**时，工具会把中文写坏成 ASCII `?`（如注释变 `????`）；或把 GBK 字节当 UTF-8 解码后再写回，导致整文件中文变 `?`、且再转 GBK 也救不回（内容丢失，非单纯编码问题）。
- **规避**：要往 GBK 文件加中文，**一律用 PowerShell `[Text.Encoding]::GetEncoding(936)` 读/写**，别用 SearchReplace 写中文；只改 ASCII/代码可用 SearchReplace；若文件已 `?`-化且非 git 管理（如 `.trae/rules/*.md`），只能靠**备份覆盖 + 重加**，务必先存好每日备份。
- **发现**：菜单反向手势/视频设置页这批改动时，`menu.h/menu.c/tetris.c/sokoban.c/d2048.c/klotski.c` 及 `.trae/rules/开发注意事项.md` 中文注释被 `?`-化；恢复方式=`git checkout`(git 文件) / 每日备份覆盖 + 重加(规则文件)。
- **经验补充（2026-09，decompress.c 视频闪烁注释改中文）**：① **任何中文只要出现在命令行里（PowerShell 命令 / `python -c "..."`）就会被 trae-sandbox 破坏成 `?`**，即使脚本逻辑对也没用；② Write 工具写出的中文文件实测是 **GBK 编码**（"启用"= `0xC6 0xF4 0xD3 0xC3`），不是 UTF-8，用 `UTF8Encoding` 读会乱码、用 `gbk` 读才对；③ **可靠做法 = 全 ASCII 的 Python 脚本**：路径用 `os.getcwd()` 相对拼接（源码不含中文路径字节），脚本内 `io.open(..., encoding='gbk')` 读写，中文内容放 GBK 临时文件里由脚本读；全程中文不出现在命令行，GBK 读写一致不坏；④ Write 工具能写 GB2312/GBK（GBK 是 GB2312 超集，收 6763 常用字之外的扩展字），但"能写 GBK"≠"能直接把中文搬进 GBK 源文件"，关键瓶颈是命令行破坏中文，所以仍需脚本搬运。

## 17. 设置界面低电恢复 + 二级菜单飞快交替（2026-09，已修）

**背景**：进入设置（二级选项菜单/设置页）后低电大图标闪烁，出现：① 电池消失后填充游戏画面；② 上划菜单后电池黑色残留；③ 二级菜单与红色图标**飞快交替**闪烁（非正常几秒一次）；④ "返回游戏再上划进二级菜单，闪完后自动出现上次设置页（如亮度）"。

**settings.c/h**：新增 `Settings_Redraw()`（只重绘当前设置页、不处理触摸，供低电灭段恢复；三个 Draw 函数都整屏 `LCD_Fill(0,0,240,240,BLACK)`，故能整屏盖掉电池区）。

**main.c `main_lowbatt_restore_under_icon()`**：抽公共 `main_restore_game_under_icon()`（各游戏 switch，省 Flash），`g_settings_from_game` 分支按三条恢复：
- 条带可见(`s_video_menu_visible`)且 `s_settings_mode != SETTINGS_NONE`（条带压在**设置页**上）→ `Settings_Redraw()` + 画条带；
- 条带可见且 `s_settings_mode == SETTINGS_NONE`（条带压在**游戏**上）→ `main_restore_game_under_icon()` + 画条带；
- 纯设置页（无条带）→ `Settings_Redraw()`。

> [!WARNING]
> **坑1（判断"条带压在游戏还是设置页"）**：用 main.c 的 **`s_settings_mode != SETTINGS_NONE`**（权威、退出设置会复位），**不要用 settings.c 的 `s_mode`**。`s_mode` 只在 `Settings_Enter` 设置、**从不复位**，返回游戏后仍残留上次页面（如亮度）。曾误用 `Settings_IsPageActive()`（查 `s_mode`），导致"返回游戏→再上划进二级菜单，低电图标闪完后自动出现亮度设置页（把游戏背景画成设置界面）"。改用 `s_settings_mode` 判断后正常，并删除了不再使用的 `Settings_IsPageActive()`。

> [!WARNING]
> **坑2（二级菜单与红色图标飞快交替闪烁）**：`GameSettings_Update`（`s_video_menu_visible && s_settings_mode==SETTINGS_NONE`）**每帧全幅重绘**条带（`menu_draw_nrow_frame_only`，y=52~240 大块 DMA 双缓冲），低电红色图标叠在同区（y=79~161），两者每帧互相覆盖 → 菜单与图标"飞快交替"。游戏菜单正常是因为 `d2048_menu_bg_redraw` 等**置脏才重绘**（无脏 return），菜单静止。
> - **修复**：条带**静止态去抖**——仅当条带位置变化（滑动动画）或**刚变可见**时重绘；静止时不再每帧全幅重绘，条带变静态，红色图标恢复正常几秒一次。
> - **坑（去抖变量复位）**：去抖静态变量放 `GameSettings_Update` **函数顶部**，并在 `if (!g_settings_from_game)` 分支复位（`s_strip_prev_vis=0`）。否则退出设置的**多条路径**（尤其"顶部下滑返回游戏"那条在函数中途 `return`）都到不了复位，"返回游戏再进设置"时 `slide_y` 与上次相同 → 条带漏画。不能只在 else 分支置 0（那个提前 return 的路径到不了）。

**设置页低电恢复改区域刷新（2026-09，已修）**：设置模式（`g_settings_from_game`）低电恢复原本 `Settings_Redraw()`（内部三个 `*_Draw` 都 `LCD_Fill(0,0,240,240,BLACK)` **整屏清黑**）→ 电池图标消失瞬间整屏刷黑再重绘，会闪一下。
> [!WARNING]
> **注意坑（设置页低电恢复勿整屏清黑）**：整屏 `LCD_Fill(0,0,LCD_W,LCD_H,BLACK)` 是"先整屏黑再画内容"，低电灭段恢复会闪一下。修复：给设置页拆出**内容局部绘制**（`Brightness_DrawSlider`/`Sleep_DrawBody`/`Orientation_DrawBody`，不含整屏清黑/DrawBack），新增 `Settings_RedrawRegion()`：`LCD_ClearLowBatteryOverlay()` 清图标后**只重绘电池覆盖区（x=44~210, y=79~161）内的设置页滑块/按钮/数字/箭头**，不清整屏。main.c `g_settings_from_game` 低电分支两处 `Settings_Redraw()` → `Settings_RedrawRegion()`。返回按钮 `DrawBack`（y=5~27）在电池区外，局部重绘不需画。

**【待做】2048/华容道上划菜单拖拽时电池区游戏网格黑（2026-09，暂未修）**：上划（重开菜单）拖拽/滑动中，电池上方游戏网格（y=79~110，菜单框外）被清黑后未重绘 → 显示黑色。俄罗斯方块因 `tetris_draw_menu_scene`（`g_board_dirty>=2`）每帧完整场景重绘所以正常；2048/华容道 `*_menu_bg_redraw` 进入重开菜单后 `g_grid_dirty` 清 0，**拖拽/滑动中不再重绘**。

**菜单拖拽时电池图标来回闪（2026-09，已修，写进菜单缓冲一起绘制）**：拖拽中菜单每帧整体重绘（青）覆盖电池区 + 图标每帧补红 → 电池区"青?红"来回闪。**正确方案（用户提出）：把电池图标写进菜单条带缓冲，菜单+图标一次 DMA 一起绘制**。

> - **跳过电池区**：菜单重绘跳过电池图标区（条带 `continue`），图标区不随菜单跟手移动 → **阻挡菜单动画**（用户否决）。且菜单 buf 先初始化黑，跳过会清图标。
> - **暂停/锁定闪烁**：拖拽期间强制灭/锁定图标，用户否决（要"电池正常闪烁且叠在菜单上、不阻挡动画"）。
> - **正确做法**：`menu_draw_nrow_frame_only` 生成条带 `row[]` 时，若 `g_lowbatt_showing`（图标亮段）且行在电池区（y=79~161），用 `lmbat_strip(row, ay, mx, mw)` 把电池框(2px边)+感叹号**写进 buf**（几何常量 bx=45,by=79,bw=150,bh=82、感叹号 x=111~129/y=92~128/点 y=137~155，与 display.c `LowBattery_ComputeGeo` 一致；凸点 x=195~210 在菜单右缘外，仍由 `Main_FlashLowBattery` 独立绘制）。`g_lowbatt_showing` 由 `Main_FlashLowBattery` 维护（亮段=1、灭段/恢复=0，menu.h extern）。
> - **别跳过条带**：跳过会破坏乒乓双缓冲 DMA 时序且阻挡动画；应**照常填菜单色、再叠加图标红像素**进 buf，一次发送即"菜单+图标"，动画正常、不来回闪。

## 18. WCH-LinkE 休眠设备无法烧录：OpenOCD 连接复位无效（2026-09）

**现象**：设备进入 Standby（PA8 触摸唤醒，见 §6）后，用 `编译与下载.ps1` 烧录报 `WCH-Link failed to connect with riscvchip`。

**试过且无效**：OpenOCD `reset_config srst_only srst_nogate connect_assert_srst` + `init`/`reset halt` 的"连接时复位唤醒"。报错在 `WCH-LinkE mode:RV`（适配器初始化）后立刻出现。

**原因**：WCH-LinkE 驱动要先跟芯片完成自身的 **SDI 握手**，这一步发生在 OpenOCD 能施加复位**之前**；芯片在 Standby 时两线调试口已关闭（WCH 手册：用户程序**开了休眠**/把**调试脚复用为 GPIO**，调试口失效），驱动握手必然失败。故 OpenOCD 对 WCH-LinkE 的 connect-under-reset **无效**，属于驱动层面限制，非接线问题（RST 接没接都一样）。

**可靠唤醒后烧录的办法**（选定：保持物理唤醒现状，不改代码）：
- **进 BOOT 模式(ISP)**：BOOT0=VCC、BOOT1=GND → 芯片进 bootloader（不跑会待机的用户程序）→ SWD/ISP 可连，烧完恢复 BOOT0=GND。WCH 官方对"程序开休眠/占调试脚"的标准做法。
- **手动复位时机**：按住板子 RESET（拉低），点烧录，等 WCH-Link 开始握手时**松开**，让芯片在复位后、跑待机前被抓住。
- **物理唤醒**：充电（PB6 充电唤醒）或点一下屏幕（PA8 触摸唤醒），设备醒来后再 flash。
- 开发期也可用 `DEBUG_NO_STANDBY` 编译（设备不睡，烧录随时能连），但烧的是不待机固件，不能用于测休眠。

## 19. 二级菜单低电恢复 + 菜单下滑交互（2026-09，已修）

**背景**：华容道二级菜单凸点黑、推箱子二级菜单红色凸点残留、所有游戏二级菜单下滑弹退出菜单整屏刷黑闪一帧、鱼游戏重开菜单下滑打断不跟手。

**根因1（设置模式下 full_redraw 只置脏、无人消费）**：
- 设置模式（`g_settings_from_game=1`）下 `*_update()` 不执行（main.c 各游戏分支 `if (!g_settings_from_game)` 跳过），而 `sokoban_full_redraw`/`klotski_full_redraw` 只置脏标记（`g_sok_dirty`/`g_grid_dirty`），由 `*_update()` 下一帧消费 → 设置模式下脏标记永不消费 → 低电图标灭段后凸点（菜单外）残留黑/红。
- 2048 函数开头**立即**重绘凸点格(1,3)/(2,3)，tetris 用 `draw_preview()` **立即**填充凸点，故无此问题；华容道走"纯游戏→full_redraw 设脏"是漏洞，推箱子同样。
- **修复**：
  - 华容道 `klotski_lowbatt_restore` 加 `g_settings_from_game` 分支：设置模式**只重绘凸点格子(1,3)/(2,3)**（不重绘整行 rows1-2，否则先画游戏再画菜单闪一帧，同 2048 坑）；纯游戏保持 `klotski_full_redraw()`。
  - 推箱子新增 `sokoban_lowbatt_restore()`：设置模式清凸点+重绘凸点瓦片；非设置用 `sokoban_full_redraw()`。main.c `main_restore_game_under_icon` 的 SOKOBAN case 改调它；`g_settings_from_game` 分支补"推箱子二级菜单跟手滑出期间(s_video_menu_visible=0)"兜底。

**根因2（二级设置条带下滑弹退出菜单整屏刷黑）**：
- main.c `GameSettings_Update` 顶部下滑弹退出菜单原用 `LCD_Fill(0,0,LCD_W,LCD_H,LCD_BLACK)` 整屏刷黑 → 游戏场景丢失，所有游戏背景黑闪一帧（鱼不整屏重绘故最明显）。
- **修复**：二级设置**条带**(`s_video_menu_visible` 为真)下滑**只清条带区** `LCD_Fill_DMA(VIDEO_MENU_X, VIDEO_MENU_Y, VIDEO_MENU_X+VIDEO_MENU_W, 240, g_menu_clear_color)`（条带区外场景保留），对齐一级菜单切换/返回游戏做法；设置页(`s_video_menu_visible=0`)仍整屏刷黑。
> [!WARNING]
> **坑（用 s_video_menu_visible 判断会漏推箱子）**：推箱子二级菜单用 `menu_enter_game_settings_swipe`（跟手滑出，`s_video_menu_visible=0`），与其它游戏 `menu_enter_game_settings`（`s_video_menu_visible=1`）不同。判断"是否设置模式"一律用 `g_settings_from_game`，**不要用 `s_video_menu_visible`**（否则推箱子跟手滑出期间漏恢复）。

**鱼游戏 `fish_menu_on_to_exit` 不跟手**：
- 重开菜单下滑打断进退出菜单，`game_menu_restart_to_exit` 已设 `g_exit_dragging=1`(跟手)，但 `fish_menu_on_to_exit` 又强制 `g_exit_sliding=1; g_exit_dragging=0`(直接滑入) → 唯一不跟手的游戏；klotski/tetris 的 on_to_exit 只置脏、保留跟手。
- **修复**：`fish_menu_on_to_exit` 去掉强制滑入，只恢复场景(与 klotski/tetris 一致)。
> [!NOTE]
> §13 曾按"重菜下滑打断应直接滑入(避免跟手拉很长才弹出)"写鱼；现按实际体验改为跟手(与其它游戏一致)。若跟手再遇"拉很长才弹出"，说明 `g_exit_drag_start_y`/`g_exit_drag_y` 初值需调。
